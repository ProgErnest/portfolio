# Creative Implementation Roadmap

No application implementation begins until this design package receives explicit
human approval. Each phase is independently reversible.

## Phase 0 — decision and evidence gate

**Dependencies:** none.  
**Deliverables:** approved creative thesis, route inventory, screenshot/privacy
decisions, and resolved Auction Bids repository question.  
**Human validation:** approve asymmetry, hero balance, evidence frames, and
whether any 3D proof is worth attempting.  
**Acceptance:** no unverified content or restricted asset is in scope.

## Phase 1 — static visual language

**Dependencies:** Phase 0.  
**Work:** extend tokens and compose one static specimen for field, rail, proof,
EP signature, system map, and evidence frame.  
**Checks:** both themes, all text readable, French wrapping, keyboard focus,
mobile/tablet/desktop composition.  
**Exit:** no generic card/gradient convention and no content loss.

## Phase 2 — motion primitives

**Dependencies:** Phase 1.  
**Work:** add the smallest shared reveal, reduced-motion, cleanup, and route
progress primitives. Implement no page-wide choreography yet.  
**Checks:** static no-JS behavior, reduced motion, back/forward navigation,
duplicate-listener check.  
**Exit:** motion tokens are centralized and content never depends on motion.

## Phase 3 — shell and Home

**Dependencies:** Phases 1–2.  
**Work:** route-aware EP field, single Hero sequence, project trajectory strip,
and stable navigation/footer composition.  
**Checks:** English/French parity, theme persistence, no Hero layout shift,
mobile no-pointer fallback.  
**Human validation:** approve the first lived composition before internal pages.

## Phase 4 — Projects and evidence system

**Dependencies:** Phase 3, approved media.  
**Work:** evidence index, status-preserving filters, native evidence dialog,
localized captions, and approved project-specific treatments.  
**Checks:** CSS filter fallback, keyboard dialog behavior, fictional captions,
no HSVP restricted media, Auction Bids link remains gated.

## Phase 5 — case studies

**Dependencies:** Phase 4.  
**Order:** JED, Library Management, Auction Bids, HSVP Hub.  
**Work:** feature/evidence focus, V1/improvement boundary, reconstruction
  treatment, and protected HSVP system map.  
**Exit:** facts remain identical to verified source data and every interaction
  has a text fallback.

## Phase 6 — About, Skills, Experience, Contact

**Dependencies:** Phase 2 and the evidence patterns from Phase 4.  
**Work:** progression compositions, evidence relationships, chronological spine,
and closing endpoint.  
**Checks:** no invented seniority, dates, outcomes, proficiency, or availability.

## Phase 7 — one optional spatial proof

**Dependencies:** all selected static routes; explicit human approval.  
**Work:** prototype S-01 or S-03 with SVG/HTML first. Only if that fails to
  express the intended relationship, test S-05 with lazy Three.js.  
**Exit:** measured benefit, static fallback, mobile simplification, reduced
  motion, cleanup, and no critical-path regression. Remove it if novelty is the
  only benefit.

## Phase 8 — quality and release readiness

**Dependencies:** selected prior phases.  
**Checks:** format, lint, Astro check, build, critical routes, internal links,
assets, themes, languages, keyboard, reduced motion, responsive viewports,
console errors, privacy, and performance measurements.  
**Exit:** documented findings and human release approval; no deployment or commit
  is implied.

## Delivery order

Static system -> motion primitives -> shell/Home -> Projects/evidence -> case
studies -> About/Skills/Experience/Contact -> optional spatial proof -> quality.
