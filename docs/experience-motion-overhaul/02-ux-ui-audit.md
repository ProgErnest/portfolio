# UX/UI Audit

## Overall assessment

The current portfolio is coherent, legible, accessible in structure, and accurate in its use of verified content. Its weaknesses are visual personality, differentiated page identities, and insufficient interaction depth. Most of the experience is currently composed from the same editorial primitives: ruled borders, restrained cards, two-column sections, and simple lists.

The visual direction is technically credible, but it reads more like a premium documentation system than an immersive creative-engineering portfolio. The transformation should be expressive without compromising the precise, evidence-led voice.

## Home

### Verified successful elements

- Strong, correctly sized English and French H1 statements.
- Clear two-column Hero hierarchy.
- The EP monogram is distinctive and provides a compact brand signal.
- The project and skills lists expose content without visual overload.
- Dark and light themes use consistent semantic tokens.
- The page remains useful without animation.

### Current limitations

- The large circular EP construction competes with the headline rather than amplifying it.
- The rest of the page becomes an evenly paced sequence of bordered sections.
- Project entries lack visual evidence and project-specific imagery.
- The contact and experience previews feel like deferred placeholders in a live homepage.
- The headline, project lists, and EP mark do not yet establish a unique story of systems thinking.

### Qualitative rating

| Axis | Rating | Justification |
|---|---|---|
| Art direction | Moderate | The green/blue technical identity is coherent but still restrained. |
| Visual richness | Low to moderate | Strong typography, but limited depth and visual contrast. |
| Interactivity | Low | Mostly navigation and standard links. |
| Motion | None verified | Static composition only. |
| Immersion | Low | No progression or spatial narrative. |
| Consistency | High | Shared margins, borders, and typography recur clearly. |
| Responsive | Good | Collapses correctly, though mobile could gain more personality. |

## Projects index

### Verified successful elements

- Status is presented explicitly.
- The CSS-only filters are keyboard-operable and do not require JavaScript.
- The list preserves useful information in non-JavaScript and unsupported-browser contexts.
- Project names, status groups, and navigation are easy to scan.

### Current limitations

- The index does not communicate each project’s visual or technical personality.
- Status groups are categories, not a narrative.
- The narrow textual rows resemble a table or status log.
- Filtering has no clear visual count or contextual transition.
- There is no evidence preview until the detail route.

### Qualitative rating

| Axis | Rating | Justification |
|---|---|---|
| Art direction | Moderate | It inherits the global system but has little project-specific character. |
| Visual richness | Low | Text and status rules dominate. |
| Interactivity | Moderate | CSS filters work, but filtering is visually quiet. |
| Motion | None | Filtering changes layout without transition. |
| Immersion | Low | No project imagery or narrative progression. |
| Consistency | High | Good continuation of global patterns. |
| Responsive | Good | Reflows to narrow rows without clipping. |

## Primary UX risks

1. Overusing the same two-column and rule-based section pattern could turn the overhaul into a visual refresh rather than an experience redesign.
2. Animating every card or heading would produce generic motion and obscure content.
3. Adding 3D or a heavy pointer system to every page would weaken performance and credibility.
4. Making status or limitation copy more prominent could reduce recruiter readability.
5. A large project media treatment must respect the approved confidentiality constraints.
