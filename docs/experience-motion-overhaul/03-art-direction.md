# Recommended Art Direction

## Direction summary

Evolve the portfolio toward **“Systems Engineering Field Notes”**: an editorial, technically precise portfolio that feels like a premium engineering publication and a live system model, rather than a creative-developer template.

The existing green/blue identity remains valid. The personality should come from asymmetric editorial layouts, a deliberate EP system, instrument-like linework, evidence fragments, and one memorable spatial device per route family.

## Proposed palette

The existing semantic tokens are the strongest foundation and should remain:

- Page light: `#F5F7F9`
- Surface light: `#FFFFFF`
- Raised light: `#E9EEF2`
- Page dark: `#101820`
- Surface dark: `#182631`
- Raised dark: `#203542`
- Green: `#087F59` / `#5CD6A2`
- Blue: `#1E6FAE` / `#78B8F4`
- Focus: `#0B6EA8` / `#95C8FF`

The overhaul should add only utility values that are directly justified:

- A faint technical grid value for large empty fields.
- A signal amber or warm neutral only for system-state communication if needed.
- No large gradients, aurora fields, rainbow effects, or decorative glow.

## Typography

Keep the approved families:

- Space Grotesk for display and page identity.
- Inter for content and controls.
- JetBrains Mono for coordinates, statuses, technical labels, and evidence metadata.

Make typography structural rather than decorative:

- Hero statements use a tight, editorial scale.
- Internal H1s use an intentionally narrower measure.
- Technical metadata is reserved for real meaning.
- No generic uppercase-eyebrow repetition across every section.

## Composition principle

Use **systems-as-layout**:

- One broad evidence or thesis area.
- One narrow annotation or status rail.
- Fine connectors and ruled boundaries.
- Asymmetrical desktop grids with a disciplined mobile collapse.
- Large title blocks, but not oversized repetition.

Avoid:

- A card in every grid cell.
- Numbered marker patterns for sections that are not sequences.
- Every heading in a pill or with the same eyebrow treatment.
- Floating glass panels for every component.
- Decorative gradients that imply product data but represent no real system.

## Core visual idea

Build the EP monogram into a **continuous system signature**:

- A compact mark in navigation.
- A larger construction in the Hero.
- A project-specific EP coordinate or connector on case studies.
- A closing signal in the footer.

The visual construction should evolve per route, not replace the existing identity:

- Home: composition and direction.
- Projects: evidence and architecture.
- Experience: chronological progression.
- About: working method.
- Skills: capability map tied to evidence.
- Contact: direct close and accessible channels.

## Imagery and evidence

The portfolio should use approved screenshots only:

- JED, Auction Bids, and Library Management already have approved public captures.
- HSVP Hub should remain evidence-led by text unless a future owner-approved, risk-free artifact is provided.
- Each capture needs a frame, meaningful caption, and clear fictional/non-result disclosure.

If future captures are added, use progressive disclosure:

1. Thumbnail or static image.
2. Enlarged lightbox or expanded view.
3. Caption and evidence boundary.
4. No claim beyond the approved content.

## Light and dark themes

Dark mode should feel like a technical instrument field: graphite surfaces, blue and green status channels, and crisp boundaries. Light mode should feel like a premium engineering notebook: cool paper surfaces, high contrast, and sparse green/blue emphasis.

Theme transitions should be treated as a cross-fade or class-level token update, never a full page reload or layout shift.

## Human validation decisions

Before implementation, validate:

- Whether “Systems Engineering Field Notes” is the preferred creative theme.
- The Hero’s desired balance between typography and the EP construction.
- The level of editorial asymmetry.
- Whether project screenshots should use visible frames or full-bleed evidence panels.
- Which, if any, 3D or WebGL concept is worth prototyping.
